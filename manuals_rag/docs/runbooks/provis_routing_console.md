# PROVIS Compute Control

Target: the existing DigitalOcean inference gateway, `/routing` on its private Tailscale HTTPS origin.

Enable `INFERENCE_WORKER_ADMISSION_MODE=entra_enrolled` to derive worker membership from current company Entra enrollment and each node's server-approved applications. New registered nodes participate without editing a name list. Pairing-only, foreign-tenant, revoked, stale-credential and stale-endpoint records cannot widen membership. Signed heartbeats, application identity, capacity and model checks remain required. Empty authorized pools fail closed.

The console is enabled with `INFERENCE_ROUTING_CONSOLE_ORIGIN` set to its exact HTTPS origin and `INFERENCE_ROUTING_RULES_PATH` set to a private, service-writable JSON file. The UI and APIs share the existing gateway service; no new public listener or application credential is created. Microsoft device sign-in must validate as the configured owner and match a current Entra enrollment. Session capabilities use Secure, HttpOnly, SameSite=Strict cookies. Mutations require the exact origin, a bounded JSON body and a live owner session. Tokens, device credentials, node secrets and prompt content are excluded from UI state.

Controls include automatic or selected worker membership per application, application/node availability, preferred workers, per-application worker priorities, global node priorities and fallback to other eligible workers. Preferences never grant enrollment or application permissions. Preferred workers take precedence among eligible workers; priority weights choose within that pool. Fallback is admission-time selection only, with no replay of an ambiguously dispatched request. This is worker routing priority, not a preemptive cross-application job queue or cloud-provider fallback.

The Nodes page also offers the existing owner-only, exact-worker diagnostic for a catalogued model already loaded on that worker. Its fixed synthetic prompt, eight-output-token limit, ten-second deadline, no preparation/download/eviction rules and disconnect cleanup are unchanged.

Every save requires a five-minute preview bound to the exact normalized document, owner session and current revision. Concurrent/stale edits fail. Saves atomically persist a new revision and up to 20 previous revisions in one private store. Restore loads a prior revision for preview and creates a new revision when applied. Rules affect new requests without restarting the gateway; running work is preserved.

Validation: full Windows inference regression **395 passed, 1 skipped, 2 deselected**. The exclusions remain the real Linux peer-credential/flock GUI test and two Linux symlink activation tests that need unavailable Windows privileges. Security coverage includes company enrollment, revocation, empty pools, caller-policy bypass, owner-only sign-in, cookie protections, CSRF, replay protection, update signatures, preview binding, concurrent revisions, persistent restore, routing priority and pre-dispatch fallback. The local browser fixture uses synthetic data and is not part of the production package.

Deploy only the pinned gateway/module/assets delta with backups and rollback. Preserve live monitor support, enrollment state, signed release catalogs and unrelated services. Start with empty routing overrides so all approved company-enrolled workers participate automatically. Reverify the owner browser sign-in and the separately approved bounded Dell model check after deployment. Second employee verification remains deferred.
